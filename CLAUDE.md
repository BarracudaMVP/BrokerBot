# Ticket Escrow Bot

Telegram-бот для гарантов сделок по перепродаже билетов. Бот — учётная система: ведёт сделки, статусы, логи переписки, скам-лист, рейтинг и отзывы. **Деньги бот не двигает** — переводы делает гарант вручную, бот фиксирует факты по кнопкам.

Полная спецификация: `docs/SPEC.md`. Читай её перед любой задачей, связанной с логикой сделок, ролями, рейтингом или БД.

## Стек

- Go
- `github.com/go-telegram/bot` — Telegram Bot API
- `github.com/jackc/pgx/v5` — Postgres
- `github.com/pressly/goose/v3` — миграции (папка `migrations/`)
- Конфиг через env: `BOT_TOKEN`, `DATABASE_URL`, `LOG_CHANNEL_ID`, `ADMIN_IDS`, `TIMEZONE`, `CARD_HASH_SECRET`

## Правила

- Все переходы статусов сделки — только через функцию переходов в `internal/domain`. Она проверяет допустимость перехода, роль пользователя, блокирует строку сделки (`SELECT ... FOR UPDATE`) и пишет в `deal_status_log`. Никаких прямых `UPDATE deals SET status`.
- Каждое нажатие inline-кнопки проверяет роль нажавшего: кнопки в группе видят все.
- Пользователей идентифицируем только по `tg_id`, никогда по username.
- Деньги — `BIGINT` в минимальных единицах. Время — `TIMESTAMPTZ` в UTC, в интерфейсе — в часовом поясе из `TIMEZONE`.
- Номера карт в скам-листе — только HMAC-хеш + последние 4 цифры.
- Состояние пошаговых диалогов и все дедлайны хранятся в БД, не в памяти: бот должен переживать перезапуск без потери данных.
- Рейтинг в `users` — кеш; источник правды — `rating_changes`.
- Все тексты бота — на русском, в `internal/bot/texts`.
- Сообщения в группах сделок копируются в лог-канал сразу при получении (удаления бот не видит), правки — как новые версии.
